Lesson 06 / about 10 minutes

A timeout is an interruption, not cleanup.

Learn what Effect.timeoutOrElse guarantees, what tryPromise must do with its signal, and where process ownership belongs.

Win for this lesson: You will be able to distinguish stopping an Effect from proving that an external process and its streams are fully cleaned up.

1. What timeout does

The effect-smol documentation describes timeoutOrElse as interrupting the source when the duration is reached, then lazily evaluating the fallback.

Effect.timeoutOrElse(runProcess(args), {
  duration: "15 seconds",
  orElse: () => Effect.fail(timeoutError)
})

This changes the Effect result. It does not automatically understand the process handle created inside runProcess.

2. Pass interruption to the external API

Effect.tryPromise supplies an AbortSignal. The wrapped operation must connect that signal to the external operation:

Effect.tryPromise({
  try: async (signal) => {
    const process = Bun.spawn({ cmd: args, stdout: "pipe", stderr: "pipe" })
    const kill = () => process.kill()
    signal.addEventListener("abort", kill, { once: true })
    // collect output and await exit
  },
  catch: toProcessError
})

This is necessary, but it is not the complete ownership story. Calling kill starts termination; it does not prove that the child has exited or that all output readers have finished.

3. Acquire, use, release

The effect-smol resource example uses Effect.acquireRelease to pair creation with cleanup:

const resource = yield* Effect.acquireRelease(
  acquireProcess,
  (process, exit) => releaseProcess(process, exit)
)

The release action runs when the surrounding scope closes, including failure and interruption. This makes ownership explicit instead of relying on every caller to remember cleanup.

4. The interface question

Ask who owns the process:

  • If runProcess owns it, runProcess must guarantee exit and stream cleanup before its Effect completes or is released.
  • If a scoped process resource owns it, the resource's release action must terminate and await it.
  • attempt should not need to know how Bun processes are cleaned up.

A good interface does not merely expose kill(). It exposes a completion guarantee: after the Effect is done, the owned process is no longer running.
