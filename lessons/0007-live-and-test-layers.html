Lesson 07 / about 10 minutes

One interface, different layers.

Use the same typed service contract for production behavior and deterministic tests without pretending that every implementation detail needs an abstraction.

Win for this lesson: You will be able to explain what belongs in a live layer, what belongs in a test layer, and how Layer.provide makes the choice explicit.

1. The service is the seam

class CurlService extends Context.Service<CurlService, {
  runJson: <S>(schema: S, request: CurlRequest) =>
    Effect.Effect<Decoded<S>, CurlError | SchemaError>
}>()("SpotUI/CurlService") {}

The callers depend on this contract. They do not depend on Bun.spawn, process handles, or the cleanup algorithm.

2. The live layer

const CurlServiceLive = Layer.effect(
  CurlService,
  Effect.gen(function* () {
    const runJson = Effect.fn("CurlService.runJson")(
      function* (schema, request) {
        // spawn curl, classify status, parse, decode
      }
    )
    return CurlService.of({ runJson })
  })
)

The live layer owns Bun, curl, cleanup, status classification, and retry policy. These mechanics are not visible to Spotify API callers.

3. The test layer

const CurlServiceTest = Layer.succeed(CurlService, {
  runJson: (_schema, request) => {
    if (request.url.endsWith("/me/playlists")) {
      return Effect.succeed(fakePlaylistsResponse)
    }
    return Effect.fail(new TestCurlError({ message: "Unexpected request" }))
  }
})

The test layer has the same interface but no network, process, or credentials. It can return successful decoded values or deliberate typed failures.

4. Provide the layer at the boundary

const program = Effect.gen(function* () {
  const api = yield* SpotifyApi
  return yield* api.listPlaylists("test-token")
}).pipe(
  Effect.provide(SpotifyApiLive),
  Effect.provide(CurlServiceTest)
)

The effect-smol layer guidance distinguishes focused layers from production wiring. Tests should make their dependencies visible rather than allowing a service layer to silently replace a fake with a live implementation.

5. Two kinds of tests

TestLayerProves
Spotify API behaviorTest curl layerDomain mapping, schema selection, and typed error handling.
Process integrationLive curl layerActual curl invocation, status parsing, timeout, and cleanup.

This is why keeping Bun concrete does not prevent testing. You use a fake at the service boundary for most tests and reserve live tests for the process boundary itself.
