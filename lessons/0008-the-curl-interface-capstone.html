Lesson 08 / about 15 minutes

Assemble the boundary.

Turn the lessons into one interface that makes the current curl mistakes difficult to express.

Win for this lesson: You will be able to review a curl interface by its guarantees and identify which implementation layer owns each guarantee.

1. The public contract

A target shape is:

interface CurlServiceShape {
  readonly runJson: <S extends Schema.Constraint>(
    schema: S,
    request: CurlRequest
  ) => Effect.Effect<
    S["Type"],
    CurlProcessError | CurlJsonError | Schema.SchemaError,
    S["DecodingServices"]
  >
}

The exact names may change with the Effect version, but the contract says four important things:

  • The caller chooses the response schema.
  • The result is decoded, not unknown.
  • Transport, JSON, and schema failures remain distinguishable.
  • Schema-required decoding services are not silently erased.

3. The wiring rule

// Focused service layer: requires CurlService
const SpotifyApiLive = Layer.effect(SpotifyApi, ...)

// Application wiring: choose the implementation once
const LiveAppLayer = SpotifyApiLive.pipe(
  Layer.provide(CurlServiceLive)
)

// Test wiring: substitute without changing SpotifyApi
const TestAppLayer = SpotifyApiLive.pipe(
  Layer.provide(CurlServiceTest)
)

This is the interface payoff. The Spotify API layer cannot accidentally replace a test dependency with a live process implementation.

4. Review the current mistakes

A sound interface and ownership model exposes the current failures:

  • The misspelled curl flag belongs to argument construction tests.
  • The nested Effect belongs to generator sequencing.
  • The missing status parsing belongs to transport response classification.
  • The missing HTTP failure mapping belongs to the transport error boundary.
  • Raw credentials in error args violate the error data contract.
  • Unawaited process cleanup violates the process ownership contract.
  • Hidden live layer provisioning violates dependency composition.

Which layer should SpotifyApiLive require rather than secretly provide?

Capstone practice

  1. Write the one-sentence guarantee of CurlService.runJson.
  2. Name the three failure families it should expose.
  3. State one reason SpotifyApiLive must not provide the live curl layer internally.

Reply with your three answers. After that, we can either design the implementation step-by-step or begin a test-first repair of src/service/curl.ts.
